# Homebody War Room — Hygiene Agent

> Adapted 2026-10-15 from the Leasing AI War Room hygiene agent. When Catherine, Cal, or Zack says **"run the hygiene agent"** or **"run hygiene"**, the agent reads this file and executes it. Editing this file is how we change the agent's behavior.

---

## Purpose

Keep the Homebody War Room Mission Control clean and the team coordinated by:

1. **Auto-fixing data inconsistencies** that should never live in the surface (past-due dates with no note, missing measures, function-named owners)
2. **Drafting courtesy DMs** to owners of items that need a status touch — never sending without explicit approval

The agent reduces the cost of running this Mission Control. If a rule starts to feel like nagging, tighten or remove it.

## When invoked

- Scheduled: Monday and Thursday mornings, MDT (the huddle is twice weekly; run the morning of each)

## Always-do, every run, in order

1. **Pull latest from git.** Do not trust local state.
2. **Read current state** of `src/data/tracks.json`, `src/data/clients.json`, `src/data/actions.json`, `src/data/decisions.json`, and every file in `src/data/pages/`.
3. **Apply data hygiene rules** (auto-fixable). Stage as edits, summarize for review.
4. **Apply messaging hygiene rules** (draft only).
5. **Surface results** as one consolidated review batch. Edits stay staged and uncommitted. DMs stay drafted and unsent.
6. **Wait for explicit approval** before committing or sending.

## Data hygiene rules (auto-fix, stage for review)

| # | Rule | Action |
|---|------|--------|
| D1 | Track not complete, `due` is an ISO date in the past, no `note` | Set `note: "Due date passed; new date needed"`, `noteTone: "alert"` |
| D2 | Track complete, `due` still set | Leave `due`; clear any alert note |
| D3 | Track not complete, `due: null`, no `note` | Set `note: "Date needed"`, `noteTone: "alert"` |
| D4 | Track `owner` matches a function name (`Product`, `CS`, `Implementation`, `Engineering`, `TBD`) | Replace with `"Owner to confirm"` |
| D5 | Track `measure: null` and not complete | Flag for review (do not invent a measure) |
| D6 | Track has `page` set but no file at `src/data/pages/<page>.json` | Flag for review |
| D7 | Client row `tracks` references a track number that does not exist | Flag for review |
| D8 | Decision `status: "open"` with `due` in the past | Flag for review; it goes to the top of the huddle agenda |
| D9 | Page `stats` tile with `value: null` and no `needs` | Set `needs` to the page owner |

Edge cases: a track with an existing non-null note is already acknowledged; leave it. Tracks owned by Catherine are flagged, not auto-edited.

## Messaging hygiene rules (draft only, NEVER auto-send)

| # | Rule | Recipient | Message asks for |
|---|------|-----------|------------------|
| M1 | Track with a past-due date | Track owner | Realistic new date |
| M2 | Track with no date | Track owner | Committed date |
| M3 | Track or client thread with no `updates` entry in the last 7 days and heat `burning` or `active` | Track owner / client CSM | What changed, or confirm nothing did |
| M4 | Track or page with `Owner to confirm` | Surface Area Coordinator (from `areas.json`) | Name the person |
| M5 | Open action item | Action owner | ETA and unstick offer |
| M6 | Page `stats` tile with `value: null` | The `needs` person | The number and its source |
| M7 | Item created today or within the last business day | Same owner, framed as a heads-up, not an ETA prompt | — |

### Consolidation

- **One DM per recipient.** Combine all items for the same owner into one numbered list.
- Skip recipients with zero eligible items.

### Exclusions

- Complete tracks, decided decisions, complete actions.
- Pings sent within the last 48 hours for the same item.
- Items due **today**: let the day play out. Past-due means yesterday or earlier.

Format rules: numbered lists, bold titles, em-dash before the state, uniform closing ask, both links labeled, italic suffix, first names only, gentle tone.

## Approval flow (CRITICAL)

The agent **never auto-sends and never auto-commits**. Every run produces a summary of staged edits and a batch of drafted DMs. Approval phrases:

- **"commit the fixes"** → commit and push staged edits with a clear message
- **"send drafts 1, 2, 3"** or **"send all"** → send approved DMs via Slack MCP
- **"redraft #2 to say X"** → revise and re-present
- **"skip"** or silence → nothing happens
